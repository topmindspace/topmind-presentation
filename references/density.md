# 信息密度 · Density（论点 + 证据 + 解读）

> **定位**：内容页「装多少、怎么组合」的唯一契约。与 `layout-grammar.md`（怎么摆、留白）互补：那里管空间秩序，这里管**每页承载的信息量**。门禁：`scripts/check_density.py`（单源 `scripts/lib_density.py`）。

## 一、为什么要这份规则

M7 诊断（四份示例 + Q1 家庭储能，共 63 个内容页）发现：图表页 20 页里有 19 页是「一张图 + 一句结论」或「图 + 一两条要点的薄文本框」。原因不在单页，而在链路：

| 环节 | 旧规则 / 默认值 | 后果 |
|---|---|---|
| 规则文档 | 「一页一图，注解只走 soWhat / footnote，不在图内塞正文」「一屏只一个视觉重心（图大就不要同时放巨号数字）」「一页只讲一张图，配一行结论」 | 图表页天然只剩图 + 结论条 |
| 模型 schema | 图表页的 optional 字段里没有 `points`，也没有关键数字字段 | 写模型的人（和 AI）根本不会填解读 |
| 版式库 | `bar` 默认匹配「通栏主图」 | 无要点时图表铺满版心，看起来「满」，信息却很少 |
| 渲染器 | 无 `points` 即主图满宽；环形图右侧用图例卡撑满 | 填充率门禁通过，密度无人管 |
| 门禁 | 只有填充率（underfill）和溢出检查 | 「放大铺满」被当成合格，信息量不计 |
| 骨架 | scaffold 图表页只给 chart + 「一行含义（≤60 字）」 | 起稿即低密度 |

## 二、调研结论（只借鉴理念）

**咨询报告（麦肯锡 / BCG 一类）**：标题是完整的结论句；正文约一半页面是「左图约 55–60% 宽 + 右侧 2–4 条解读」；解读写**原因与含义**，不复述图上的数；证明标题的那个数字单独放大（callout）；图下有 takeaway 条与口径来源行；复杂页用对齐的小图组、桥图 + 编号注释、图 + 对照表。

**发布会 / 路演**：一页一个观点，但「一个观点」≠「一个元素」：大数字 + 一句支撑、主图 + 2–3 个关键数字、产品图 + 3 个卖点、对照（旧 vs 新）都很常见；现场讲的页可以更疏，发出去自己看的页要能脱离讲者读懂。

**密度分档**（按「证据类元素种类 / 正文字数」）：

| 档位 | 典型组合 | 适用 |
|---|---|---|
| 疏（休止） | 封面、章节幕、金句、收尾 | 节奏页，合法留白，不参与密度门禁 |
| 中（演示） | 结论标题 + 主图 + 2–3 条解读 + 2–3 个关键数字 | 发布会、路演、汇报现场 |
| 密（研究） | 结论标题 + Exhibit + 3–5 条解读 + 关键数字 + 口径 / 待核实 | 研究报告、预读材料、发出去自己看 |
| 结构（架构） | 主结构图 + 2 条说明（选型理由 / 风险） | 架构评审 |

## 三、复合版式（版式库 `data` 家族）

| 版式 id | 组成 | 模型写法 |
|---|---|---|
| `chart-readout` | 关键数字条 + 主图（约 60%）+ 编号解读栏 | `bar` / `donut` / `exhibit` + `points` + `keyMetrics` |
| `chart-dual` | 双图对照（各带图题）+ 解读行 | 再加 `chart2:{labels,values,cap,…}` |
| `chart-minis` | 主图 + 2 个小图（small multiples）+ 解读行 | 再加 `minis:[{cap,labels,values,unit},…]`（最多 2 个） |
| `chart-band` | 主图保持原几何 + 底部「关键数字 + 解读」带 | 信息图 / 热力 / 矩阵 / 结构图 / 指标页 + `points`（+ `keyMetrics` ≤2） |
| 图文混排 / 配图加说明 / 案例卡 | 沿用 `text-media`、`media-half`、`feature-cards`、`bento` | `split` / `image` / `cards` |

HTML 与 PPTX 同构：判定在 `lib_density.compose_on`（Python）与 `composeOn`（build_pptx.js），两端同口径。`compose:"off"` 可关闭（例如数据充分、确实只需要一张大图的过渡页）。

## 四、模型契约（每页 = 论点 + 证据 + 解读）

1. **论点**：标题写结论句（含数字与比较），不是话题。
2. **证据**：图表 / 表格 / 数据点；口径与来源进 `footnote` / `source`。
3. **解读**：`points` 写「看到什么 → 意味着什么」，**不复述图上已标的数**，写原因、对比、下一步。
4. **图表页必须同时有解读要点和关键数字**：
   - `points`：演示 ≥2 条、研究 ≥3 条、架构结构图 ≥2 条说明；
   - `keyMetrics`：2–4 个（`[值, 说明]`）；缺省时单序列图表**按数据推导**（最高 / 最低 / 首末变化或极差，环形为占比最高 / 前两项合计），只做算术，不编造。
   - **解读要讲原因、影响、下一步**：每条要点可以带一个数字作锚点，但后半句必须回答「为什么会这样」「意味着什么」或「所以先做什么」。写法：`[事实（≤1 个数字）, 原因 / 影响 / 下一步]`。
     - 反例：`["制造 3 家居首", "占 33%"]`、`["线上占比逐年提升", "40% → 52% → 61%"]`——只是把图上的数换个说法念一遍。
     - 正例：`["制造与金融合计 55%", "共同点是流程标准、容错边界清晰，因此可直接复制"]`。
   - **只用已有事实**：原因和下一步必须来自本页或本稿已有的数据、口径、结论条（`soWhat`）、来源；没有依据就写「影响」（算术推出的对比），不要编原因、不要编建议的数字。
   - 小图组 `minis` 最多 2 张（`DENSITY_MINIS_MAX` FAIL），第 3 组数据拆页或并入主图。
5. `soWhat` 是 takeaway 条，**不能替代解读**；`note` / `footnote` 是口径，不计入正文。

缺解读时：渲染器在终端提示（`[render_from_model] 信息密度 FAIL …`），能推导关键数字的图表自动升级为复合版式；`check_density.py --strict` 拦截。

## 五、门禁（`check_density.py`，三模式分档）

| 模式 | 正文字数下限 | 上限（超过提示拥挤） | 图表页解读条数 | 图表页数据点 |
|---|---|---|---|---|
| presentation | 40 | 320 | ≥2 | ≥3 |
| research | 80 | 900 | ≥3 | ≥3 |
| architecture | 50 | 520 | ≥2（结构图说明） | — |

- 正文字数不含标题、eyebrow、来源、结论条；数据点 = 图表数值 + 正文中的数字。数据点 ≥6 的纯指标 / 表格页免文字下限。
- 章节、引言、封面、收尾不参与。
- **复述检查（M8）**：
  - `DENSITY_ECHO`（WARN）：要点含数字，但去掉数字、图表标签、单位和「最高 / 增长 / 占比」这类复述用词后，剩下的实义字不到 8 个，且没有原因 / 影响 / 下一步的信号词——判为复述。一页过半要点是复述即提示。
  - `DENSITY_NO_INSIGHT`（WARN）：一页的要点里没有任何一条讲原因 / 影响 / 下一步（信号词见 `lib_density.REASON_MARKERS`：因为、由于、导致、意味、说明、因此、建议、下一步、需要、关键、瓶颈……）。
  - 示例与 CI 走 `--strict`，WARN 也要清零。
- 留白仍然重要：上限只提示，不硬拦；解读带最多 2 个关键数字 + 3 条要点（`DENSITY_BAND_CAP`）。

## 六、插图与图标

| 场景 | 用法 | 禁止 |
|---|---|---|
| 用户提供的照片 / 产品图 | `image`（`media-half` / `media-full` / `media-grid`），配图注写清是什么、何时何地 | 无来源的图当证据 |
| 截图（界面 / 后台 / 报表） | `media-half` 左图右文，右侧 2–3 条说明指向截图里的具体位置 | 截图里看不清的文字当正文 |
| 示意图（流程 / 结构 / 关系） | 优先用结构页型（`diagram` / `lane` / `network` / `steps`）由数据生成，可编辑 | 用位图示意代替可编辑结构 |
| 图标组合 | 语义图标库（`assets/icons/`）点题：卡片标题、步骤节点；同页 ≤6 个 | 图标当装饰堆满、一页多套图标风格 |
| AI 生成图 | 仅可作氛围 / 封面背景，且必须标注「示意图（AI 生成）」 | **把 AI 生图当成事实证据**（产品实拍、现场、数据图、人物） |

没有真实图片时用占位框（`imageSpec` 配图占位约定），写清「需要什么图」，不要用生成图冒充。
