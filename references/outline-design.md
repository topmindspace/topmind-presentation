# 内容架构与大纲设计（生成前必经阶段）

> **报告的质量上限在写第一个字之前就定了**——由「证据底稿 + 故事线 + 大纲 + 逐页规划」决定，不由辞藻和样式决定。
> 本规范定义生成前的内容架构流程：**意图解析 → 证据表 → 故事线脑暴 → SCR 收敛（含主张树）→ 大纲 → 逐页规划 → 用户确认（按需）**。
> 形式参数（模式/风格/主题/篇幅/交付格式）由 SKILL.md 六项问询收集；本文件管的是**内容本身怎么想、怎么组织**。

---

## 一、内容架构七步法

```
① 意图解析    谁看？什么场景？要回答什么决策问题？→ 核心主张一句话
② 证据表      把材料变成可审计的底稿（来源位置/期间/单位/置信度/冲突/caveat/含义/推荐视觉）
③ 故事线脑暴  2–3 条可选故事线 + issue tree / hypothesis tree，比较证据强度与风险缺口
④ SCR 收敛    推荐故事线收敛为 Situation–Complication–Resolution + 主张树（3–5 分论点，MECE）
⑤ 大纲设计    分论点分组为章；章标题 = 该章结论；标注每章承载形态与密度
⑥ 逐页规划    每页一张规划卡：主张 / 内容单元 / 信息密度与组件清单 / 版式 / 图表 / 细节处理
⑦ 用户确认    长报告与敏感内容必确认；小报告可跳过（默认按规划走）
─────────────────────────────────────────────────────────────
之后才进入生成（SKILL.md 工作流），规划即填写 REPORT_MODEL 的直接输入
```

## 〇、轻量最小集（Fast / 轻量路径 · 非七步）

> **不强迫完整七步**，但禁止「零大纲直接 scaffold」。路演/汇报材料杂时尤其需要这一屏。

写在内部笔记（≤1 屏）即可：

1. **核心主张一句话**（≤30 字；含判断/数字更好）。
2. **页清单**（每行三列）：`claim`（本页主张） / `pageType` / `chart`（无图写 `—` 或 `image`/`placeholder`）。

示例：

```
主张：Q3 增长靠转化而非流量，优先修结账漏斗
1. 议程 | agenda | —
2. 转化率跌 4pt | kpi | —
3. 漏斗三段对比 | bar | funnel
4. 竞品截图+含义 | image | —
5. 行动三项 | points | —
```

之后进入 playbook §二轻量命令链。完整路径仍走下方七步法。

---

> **为什么前置证据表与故事线脑暴**：直接从材料跳到单版大纲，等于用第一条想到的叙事结构绑架全部材料——证据冲突会被静默抹平、弱枝论点会混进主张树。**先摊开证据、再发散故事线、最后收敛**，是咨询材料的标准做法。

### ① 意图解析（问自己四个问题，写进内部笔记，不进报告）

1. **谁看**：决策者 / 评审专家 / 普通听众 / 混合？（决定模式 A/B/C 与密度档）
2. **什么场景**：台上 10 分钟 / 坐读 30 分钟 / 评审会看图？（决定篇幅与节奏）
3. **要回答什么决策问题**：报告读完，读者应该做出/改变什么判断？（这是报告存在的理由）
4. **核心主张一句话**：≤ 30 字，含判断和数字更好（"X 是 Y 的第一瓶颈，优先解决可获 Z"）。
   写不出这一句 → 材料还没想清楚，先与用户澄清意图，不要开始生成。

### ② 证据表（MBB 标准 · 可审计底稿）

把源材料摊成一张**逐条可追溯**的底表。每条事实/数字/判断/建议/caveat 一行，字段固定：

| 字段 | 说明 | 示例 |
|------|------|------|
| 来源位置 | 哪个文件/哪一页/哪张表 | `材料A P12 表3` / `外部报告 [3]` |
| 期间 | 数据覆盖的时间窗 | `2024Q1–2025Q2` |
| 单位 / 口径 | 计量单位与统计口径 | `亿元，含税，全渠道` |
| 置信度 | 高（实测/官方）/ 中（第三方）/ 低（估算/预测） | `中` |
| 冲突 | 与其他来源不一致之处（**记录，不静默归一**） | `与材料B 的 42% 不一致（口径差）` |
| caveat | 适用条件、例外、限制 | `仅覆盖一线城市` |
| 含义 | 这条证据支持什么判断 | `支持"转化是瓶颈"` |
| 推荐视觉 | 该证据最合适的承载（图表/表/图示） | `漏斗图` / `密表` |

**硬规则**：
- **所有事实、数字、判断、建议、caveat 必须可追溯到源材料位置**，或明确标记为缺口（`待补：xx`）。
- **不得用常识补源材料没有的数据**；不得把外部预测当既成事实。
- 来源间数值/口径不一致 → **记录冲突，不要静默归一**；冲突本身往往是报告的洞见。
- 缺口清单单独列一节（这些是后面 `.tbd` 待核实标注与 `.flagbar` 的候选）。

### ③ 故事线脑暴（发散 2–3 条，不急于收敛）

基于证据表提出 **2–3 条可选故事线**（不是 2–3 个标题，而是 2–3 种**叙事结构**），每条给出：

- **issue tree（议题树）**：把决策问题逐层拆成子问题（MECE），标出哪些子问题**证据已足**、哪些**缺证据**。
- **hypothesis tree（假设树）**：先立假设（"瓶颈在转化而非流量"），再列**验证所需的证据**与**可能推翻它的证据**。
- **对比维度**：证据强度 / 风险缺口 / 适用受众 / 不推荐原因。

**为什么必须做**：单一故事线容易让材料迁就结构。摆出多条并写明"为什么不选另外两条"，是防止叙事自嗨的最低成本手段。

### ④ SCR 收敛 + 主张树

**SCR 结构**（全篇骨架，写进内部笔记）：

- **Situation 情境**：读者已认同的事实基线（1–2 句，不含新信息）。
- **Complication 冲突/复杂性**：打破基线的事实或变化（**报告真正的起点**——"为什么现在要看这份报告"）。
- **Resolution 解决/主张**：你要读者接受的主张与行动（= 核心主张一句话）。

**主张树**（金字塔 · 自上而下设计，自下而上验证）：

```
核心主张（一句话）
├─ 分论点 1（支撑主张的第 N 个理由，每章一个）
│   ├─ 证据 1a（来自证据表：数据 → 图表选型）
│   ├─ 证据 1b（来自证据表：案例 → 卡片/时间线）
│   └─ 含义（so-what：这一章意味着什么行动）
├─ 分论点 2 …
└─ 分论点 N …
```

**规则**：

- 分论点 3–5 个（少于 3 单薄，多于 5 合并）；**MECE**：不重不漏——同一证据不得支撑两个分论点，所有分论点合起来能撑住主张。
- **自下而上验证**：任一分论点被推翻，核心主张是否动摇？不动摇的论点是弱枝 → 删（宁可 3 个硬论点，不要 6 个软论点）。
- **每个分论点必须挂到证据表的行**（可追溯）；挂不上的分论点 = 无证据 → 删或标为缺口。
- 分论点顺序 = 叙事顺序：时间序（现状→路径→目标）/ 重要性序（最有力或最痛的在前）/ 逻辑序（问题→原因→方案）——选定一种，全篇一致。

### ⑤ 大纲设计

- 章标题写**结论**（行动标题），不写主题词：✗"市场格局" ✓"入湖表 68% 从未被查询——资产沉睡是第一问题"。
- Agenda 即大纲：条目 = 章标题（结论式），一句话说明 = 该章的关键证据预告。
- 章数与篇幅对齐：演示 8–15 页 ≈ 3–5 章；研究 12–25 页 ≈ 4–7 章；架构 1–3 图即成篇。
- 每章标注**承载形态**：论证页 / 数据证据页 / 密表页 / 图示页 / 休止页——在逐页规划里落到具体版式。

### ⑥ 逐页规划（每页一张规划卡 · 生成时直接照此填 REPORT_MODEL）

对每一页回答七项（这是 REPORT_MODEL 每个 section 的设计稿）：

| 项 | 内容 | 校验点 |
|----|------|--------|
| 主张 | 该页行动标题（结论句） | 每页标题合起来能否复述核心主张？ |
| 内容单元 | 该页并列的信息块（卡片/指标/图表/表）| 数量决定密度档（content-rules.md §四-d） |
| **信息密度** | 该页目标密度（低/中/高）+ 依据 | 与前后页形成节奏（见 §一-续） |
| **组件清单** | 主图与侧栏比例、表格/注释/图例/微图表数量、关键证据 ID、so-what | 不得在生成时降级成稀疏大字报 |
| 密度档 | L 轻 / M 中 / H 重 | 与前后页形成节奏（连续两页 H 档 → 插 L 档） |
| 版式 | `components.md` §46 按内容形态选 + `components.md` §46b 按密度定；复杂信息图见 `infographics.md` | 禁止临场发明表外结构 |
| 图表/表格 | 类型 + data-chart 标记 + 数据来源 + `chart.dataTable` 策略 | 数据可获取、口径可写清、非原生图表至少 `notes` |
| 细节处理 | 该页涉及的细节/数据如何保全（见第二节） | 无细节丢失（每条细节有去处） |

**全篇回查三问**：

1. 每一页删掉，报告结论是否受损？（不受损的页是凑数页 → 删）
2. 逐页主张连读，是否等于一条完整论证链？（断裂处补过渡页/调整章节顺序）
3. 是否有连续 3 页同版式？（模板感 → 换版式或插休止页）

### ⑦ 用户确认（按需触发 · 一次 · 不反复）

**必确认**（满足任一）：

- 研究报告 ≥ 20 页 或 演示 ≥ 12 页（返工成本高）
- 内容含未敲定的关键判断（竞争策略/预算分配/风险定性）
- 用户提供的材料量大且杂（需确认取舍口径）
- 用户明确说"先给我看大纲/框架"

**可跳过**：短报告（演示 ≤ 8 页 / 架构图）、用户给了完整成文材料只是转格式、用户说"直接生成"。

**确认载体**（宿主支持结构化选项卡时优先用卡）：

```markdown
## 内容架构确认（确认后即生成，改哪里只改哪里）

**SCR**：情境 <一句话> → 冲突 <一句话> → 主张 <核心主张一句话>

**故事线取舍**：采用 <线A>；不采用 <线B/C> 的原因：<证据缺口/风险>

**大纲**（每章 = 一个分论点，标题即结论）：
1. <章标题（结论式）> —— 关键证据：<图表/数据>

**逐页规划摘要**：
| 页 | 主张 | 版式 | 密度 | 承载 |
|---|------|------|------|------|
| 3 | … | R2 Exhibit | 中 | 柱状图[1] |
| 4 | … | R3 密表 | 高 | 对标表 12 行 |

**取舍说明**：<材料里被剪掉的弱枝与原因、待确认的 xx 占位、证据冲突项>
□ 按此生成　□ 需调整（说哪改哪）
```

用户回复"调整"时**只改指定处**（对应主张树节点），不推倒重来；用户未选择默认按此生成。确认完成后不再有内容层面的反复确认。

## 一-续、跨页叙事节奏（单页合格 ≠ 全篇好看）

> 逐页规划卡保证**单页**合格；本节保证**全篇**读起来有起伏。规划完成后按下表回查一遍。

### 1. 密度交替（呼吸节奏）

- **禁止连续 3 页同密度档**：H–H–H 会让人疲劳，L–L–L 会显得空洞。
- 推荐节奏：`M → H → L → M → H → L`（L 档用金句页/大数指标页/休止页承担）。
- 演示模式（A）天然低密度，节奏靠**版式变化**（要点页 → 大数页 → 图表页 → 金句页）。
- 研究模式（B）高密度为主，节奏靠**每 3–4 页插一张低密度页**（大引言页 / 关键结论页）。

### 2. 章节色彩递进

- 章节头（eyebrow + 主标题）承担"章节感"，**不靠换强调色**（单一强调色铁律）。
- 递进手段：章节编号递增 + 章节头留白宽度微调 + 该章主图形态变化（图 → 表 → 图）。
- 架构模式（C）用**分层带/泳道颜色深浅**表达层级递进，仍限强调色族。

### 3. 首尾呼应

- **封面标题 ↔ 收尾页主张**：收尾页的"下一步"三点必须能回应封面提出的问题（读一遍是否闭环）。
- 封面副标题给出的"范围/口径"，收尾页的 flagbar 要收口（待核实项列明）。
- 禁用 `band--deep` 作末页（浅色主题下会渲染成深色页，铁律 3）；收尾用 `.band--accent`。

### 4. 渐进揭示（阅读路径）

- 每页**左上到右下**的阅读顺序必须与论证顺序一致：先结论（行动标题）→ 再证据（图/表）→ 最后含义（so-what）。
- 同一页内**不要出现两个并列的视觉重心**（两个大图 / 大图 + 巨号数字）；要并列就分页。
- Agenda 跳转锚点必须与章标题一一对应（校验器查锚点闭环）。

### 5. 节奏回查清单（生成后自检）

- [ ] 有没有连续 3 页同密度档或同版式？
- [ ] 每章第一页是否都是同一形态（全是密表/全是图）？→ 换一页的形态
- [ ] 收尾页能否回应封面提出的问题？
- [ ] 有没有一页出现两个视觉重心？
- [ ] 从 Agenda 跳到的每一章，标题与 Agenda 条目是否一致？

## 二、细节保全策略（数据/细节密集时的承载设计）

> **原则：细节不能丢，但也不能全堆在正文里**。每一条细节必须有明确去处：主页面（决策必需）/ 图表内（数据本体）/ 图注与来源行（口径）/ 附录（备查全量）。
> 判断标准：这条细节影响读者做判断吗？影响 → 进主页面；不影响但需要可查 → 沉淀层；都不影响 → 删。

### 2.1 承载工具选型矩阵（细节形态 → 工具）

| 细节形态 | 承载工具 | 组件/页型 | 细节去哪 |
|---------|---------|-----------|---------|
| 多维数值对比（≥3 对象 × ≥4 维） | 密表 | R3 / `table` | 表内全量数值；结论列收口 |
| 时间趋势 + 阶段节点 | 折线/面积 + 里程碑标注 | `line` / E 时间线 | 数据点标在图上；口径沉来源行 |
| 构成占比（≤5 段） | 环形 + 图例数值 | `donut` | 图例带数值；中心放合计 |
| 排名 / 大小对比 | 横向条形（数值外标） | `hbar` | 数值直接标条末 |
| 双维定位 / 优先级 | 矩阵 / 散点 | R8 / `scatter` | 象限标注含义；明细沉密表 |
| 流程 / 职责 / 数据流 | 泳道（步骤内短标签） | A2 / `lane` | 步骤 ≤8 字；补充说明沉图注 |
| 系统分层结构 | 分层带（节点卡） | A1 / `diagram` | 节点短标签；职责细节沉图注 |
| 大段参数/规格/清单 | 附录密表页 | R3 变体（refs 后） | 主文只留 Top N + 指向附录 |
| 因果链 / 闭环逻辑 | 流程图（SVG） | A3 / 版式 A | 环节即节点；条件分支沉图注 |
| 增减归因 | 瀑布图 | `waterfall` | 每段标变化量；合计收口 |
| 实施节奏 / 操作步骤（3–6 步） | 步骤条 | `steps`（components `components.md` §47） | 步骤标题 ≤8 字、说明 ≤30 字；补充说明沉备注 |
| 二维强度对标（行业 × 场景等） | 热力矩阵 | `heatmap`（`components.md` §48） | 单元格数值 + 强度词；口径沉 `.footnote`；>5×5 拆附录 |
| 目标达成度（实际 vs 目标） | 达成对比条 | `bullet`（`components.md` §49） | 目标线标在条上；未达标行转中性色；明细沉备注 |
| 两期升降 / 前后对比 | 斜率图 / 哑铃图 | `slope` / `dumbbell`（`charts.md` §57/§58） | 两端都标数值；差距最大项用强调色 |
| 多对多流向 / 归因路径 | 桑基图 | `sankey`（`infographics.md` `components.md` §1） | 节点短标签；流量标在带上；明细沉数据表 |
| 份额悬殊的构成（头部集中） | 矩形树图 | `treemap`（`infographics.md` `components.md` §2） | 面积 ∝ 数值；<5% 合并为"其他"；块太小只标占比 |
| 分组分布（中位/四分位/极值） | 箱线图 | `boxplot`（`infographics.md` `components.md` §3） | 中位数值标在箱上；极值只在需读数页标 |
| 节点-边拓扑关系 | 关系网络 | `network`（`infographics.md` `components.md` §4） | 节点短标签；连接度用节点大小表达 |
| 双重编码（总量 × 构成） | 马赛克图 | `marimekko`（`infographics.md` `components.md` §5） | 列宽 = 总量、列高 = 占比；段值标在段内 |
| 构成随时间演变 | 流带图 | `streamgraph`（`infographics.md` `components.md` §6） | 系列名标在带内或图例；不标数值 |
| 层级递进 / 价值阶梯 | 金字塔 | `pyramid`（`components.md` §50） | 层标题 ≤6 字、说明 ≤24 字；≤5 层 |
| 素材图片（实拍/截图/示意图） | 图片页 / 图文页 | `image` / `.media`（`components.md` §11c） | 图注写口径与版权；数据图不用截图 |
| 讲稿口径 / 数据口径 / 来源细节 | **演讲者备注** | PPTX notesSlide（自动） | lead/soWhat/note/footnote/图表口径/数据表自动写入备注区——HTML 报告保留正文呈现，PPTX 中沉到备注 |

### 2.2 待核实内容的处理

> 细节保全的反面是**不可靠细节**：查不到出处、口径未定、需业务确认的数字与判断。

- **不进主张树**：外部数据先定来源；没有来源的数字不进主张树（见 §一）。
- **必须落地但不能裸奔**：确实要用（因为决策需要），就用**强调色标注**——`.tbd` 内联标色 + `.tbd-legend`/`.flagbar` 说明（见 `content-rules.md` 五-b）。
- **交付时明确列出**：收尾页或数据页用 `.flagbar` 逐条列明"待核实项"，并在交付说明里点出——**不要把不确定性藏进正文**。
- **口径与图片**：`.footnote`/`.fig__cap` 写清统计口径；图片必须带图注与来源。

### 2.3 超限拆分（细节超出单页承载时，按序处理）

1. **换更高密度的承载**：文字列举 → 表；表 → 图（对比矩阵→散点；参数清单→密表）。承载形态升级优先于拆页。
2. **主表 + 附录**：表格 > 16 行 → 主页面放 Top N + 「其余 N 项合并」行，**全量表放文末附录页**（「参考资料」之后，标题注明"附录：全量数据"）；两处数据口径一致。
3. **指标墙 + 明细**：指标 > 6 个 → F 指标墙页（6±2 个核心）+ 附录明细表；辅助指标合并为复合指标。
4. **图注沉淀**：图中放不下的条件/例外/口径，一律沉到 `.fig__cap` / `.exhibit__src` / `.footnote`（≤1 行/处），不在图周围加大段文字。
5. **仍放不下 → 拆页**：01a/01b 两页，下一页重复 eyebrow 标注（续）。

### 2.4 信息图三原则（细节进图时的底线）

1. **一图一主张**：图标题写结论（"试点率 61%，规模化不足两成"），不写中性描述（"企业试点情况"）。
2. **数据直接标在图上**：关键数值标在数据本体旁（条末/点侧/环内），不强迫读者查图例换算；坐标轴只做尺度参考。
3. **口径可见**：单位、统计口径、时间窗放来源行（`.exhibit__src`）；外部数据带 `[n]` 与文末参考资料双向对齐。

### 2.5 反模式（自查）

- ✗ 把 20 行数据表转成 20 个卡片/要点塞满一页（信息密度爆炸且不可比）→ 该用表就用表。
- ✗ 表格旁边再写一遍表里的数字（重复承载）→ 文字只写表不能表达的：趋势、对比、含义。
- ✗ 图表做小、细节全在下方长文里（图成为装饰）→ 图是主角，文字是解读。
- ✗ 删数据保版式（"表格太长就砍列"）→ 砍列前先走 2.3 拆分流程；口径列/时间列不许砍。
- ✗ 附录表与主表数字不一致 → 附录是全量、主表是截取，同源同口径（校验器查 Exhibit 连续性；人工核对数字一致性）。
- ✗ 复杂信息图硬塞进普通图表页（桑基塞进柱状图）→ 用 `infographics.md` 的专属页型。
- ✗ 只写结论不给证据、或只堆证据不给含义 → 每章必须"发现 → 证据 → 含义"闭环。
