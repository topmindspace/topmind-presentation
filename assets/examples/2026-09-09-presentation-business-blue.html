03 · 落地路径

从试点到规模化：两条路径的分野

堆场景路径 · 现状

  • 接入慢。每场景重复对接工具与权限。
  • 治理弱。事后审计，回退靠人工。
  • 易回退。23 家中 19 家半年内退回试点[2]。

平台化路径 · 目标

  • 接入快。统一编排，接入成本降一个量级。
  • 治理内嵌。权限、审计、回退进平台层。
  • 可放量。先行 9 家全部穿越分水岭[2]。
平台化不是可选项，而是规模化穿越分水岭的唯一共同路径。

06 · 能力地图

平台化三件套：编排、记忆、治理缺一不可

01

统一编排

  • 工具连接。千级工具统一注册与调用。
  • 任务拆解。多步规划与失败重试。
02

长期记忆

  • 任务记忆。跨会话保留目标与进度。
  • 偏好学习。组织口径与风格沉淀。
03

护栏治理

  • 权限分级。高风险动作人工确认。
  • 全程可回退。审计与回滚内嵌平台层。

HTML 与 PPTX 的分工

HTML 是阅读与演示界面，PPTX 是协作与修改格式——两者来自同一内容模型（window.REPORT_MODEL），PPTX 内全部是原生形状、文本框、表格（pictures=0），可在 PowerPoint / WPS 中继续编辑；带数据的图表为原生数据图表（chart 对象 + 内嵌 Excel，双击即可"编辑数据"）；口径、来源与 so-what 自动写入演讲者备注，不占版面。

怎么获得 PPTX

页面预览（P）· 所见即所得

点 header 的「预览」按钮查看 WYSIWYG 页序列——预览与智能体精导使用同一序列化引擎，看到的即交付所得。页面不直接导出文件（浏览器端达不到 strict 质量硬门禁）。

智能体精导 · 唯一交付通道

复制下方提示词回到 AI 对话，由本地智能体执行 extract_model.py → build_pptx.js --model → validate_pptx.py --strict，0 错误 0 警告才交付（含模型往返保真检查）。

命令序列（智能体精导）

python scripts/extract_model.py 报告.html
node scripts/build_pptx.js 报告.pptx --model=报告.model.json
python scripts/validate_pptx.py 报告.pptx --strict --model=报告.model.json
