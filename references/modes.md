# 三种报告模式 = 三种独立输出体系

> **何时读**：需要模式密度契约细节、research R1–R8 / architecture A1–A3 锁定版式时；或 playbook 与校验器阈值冲突需要仲裁时。**何时不读**：常规生成（playbook §一 契约表已够用）。
> **取节**：`python scripts/extract_snippet.py --file modes.md --section A`（B/C 同理，单字母即模式；亦可用标题关键词）。

**模式不是切换关系，而是内容呈现形式、信息密度、面向受众与场景、整体逻辑结构、布局样式的完全不同。** 一份报告 = 一种模式 + 一种风格 + 一种亮暗主题 + 一套内容；模式在生成前的「六项问询」（单次交互，见 SKILL.md）中确定，从对应模式模板起步，`data-mode` 写死在 `<html>` 上（与 `REPORT_MODEL.mode` 一致，校验器双重锁定）——**生成后页面无模式切换**。

```html
<!-- 三份独立模板，各自锁定 -->
<html data-mode="presentation"  data-style="business-blue" data-theme="light">  <!-- assets/templates/presentation.html -->
<html data-mode="research"      data-style="mckinsey"      data-theme="light">  <!-- assets/templates/research.html -->
<html data-mode="architecture"  data-style="graphite-dark" data-theme="dark">   <!-- assets/templates/architecture.html（石墨深灰深色优先，出厂 dark） -->
```

- **风格与模式正交**：9 套风格是纯视觉皮肤（色彩/字体/圆角/阴影），header 下拉可生成后实时切换查看（交付前切回选定值，`data-style` 与 `REPORT_MODEL.style` 一致）。
- **模式决定**：独立模板骨架、密度 token、组件体系、页面预算、图表尺寸策略、PPTX 页型与排版比例尺。

## 模式速选

| 模式 | data-mode | 形态定位 | 受众与场景 | 信息密度 | 典型篇幅 |
|------|-----------|---------|-----------|---------|---------|
| A 演示汇报 | `presentation`（默认） | 大字号、每屏一主张、图表大而克制 | 台上宣讲，投影远看 | 低（每屏 1 主张） | 8–15 页 |
| B 研究报告 | `research` | 咨询密排：行动标题 + 论证链 + Exhibit + 密表 + 矩阵 | 坐下来深读的决策者 | 高（空间利用最大化） | 12–25 页 |
| C 信息架构图 | `architecture` | 图为王：全幅分层带/泳道/管线 | 评审会，看结构不看句子 | 极低文字 | 1–3 张图（6–8 页，可省 Agenda） |

**意图 → 模式默认推荐**：演示/汇报/宣讲/路演 → A；研究/分析/调研/评测/对标/白皮书 → B；架构/方案拓扑/流程/数据流 → C。混合需求（研究+架构）→ 主模式 B、架构章节用 C 的图示组件。

## 三模式信息密度与内容丰富度全维对照（生成前据此设计每页）

> 三种模式不是同一份内容的"疏密调节"，而是**三种阅读契约**：A 是"3 秒一屏"的投影契约（远看、听讲），B 是"30 秒一页"的坐读契约（近看、深读、可反复查证），C 是"一眼看全结构"的评审契约（看图不看句子）。信息密度、内容丰富度、版式节奏全部由此推导。

| 维度 | A 演示汇报 | B 研究报告 | C 信息架构图 |
|------|-----------|-----------|-------------|
| 版心宽度 | 1400px | **1240px**（行宽 34–40 字，阅读友好） | **1600px**（图占满） |
| 正文字号 | 17–18px（投影够大） | **14–15px**（密排） | 默认字号（文字退到图注级） |
| h1 字号（clamp 上限） | 48px | **34px** | 48px（图才是主角） |
| 每屏主张数 | 1 个主张 | 1 个结论 + 3–6 组论据 | 1 张主图 |
| 单页文字预算 | ≤1800 字（预警·密页可偏密） | **≤3200 字** | ≤400 字（图注级） |
| 并列单元上限 | 8 | **12** | 节点 ≤24 / 泳道行 ≤6 步 |
| 表格行数上限 | 8 | **16**（密表） | —（表转图） |
| 每页图表数 | **按复杂度定面积**（V1–V4；简单图禁全幅） | 1–2 个（取尺寸下限） | 1 张全幅主图（宽 ≥85% 版心） |
| 页面高度 | 每页一屏（`--band-min`，垂直居中） | 每页一屏（紧凑 `--band-pad`） | 每页一屏（图为王，`--band-pad` 最紧） |
| 图表尺寸策略 | **随复杂度**（简单图 18–28% 高，复杂图才 55%+；极偏禁 donut） | 下限即可、不缩水 | 高度预算 500–700px |
| 论证结构 | 主张 → 证据 → 节奏休止 | **发现→证据→含义 + so-what**（每页都是论证） | 标题 → 图 → 图注 |
| 组件体系 | 通用组件 + 混排版式 A–F | **R1–R8 锁定版式** | **A1–A3 图示版式** |
| 节奏休止 | 金句页（全文 1–2 处 · 强调带） | R4 指标带（每 3–4 页一处） | 收尾极简页（强调带） |
| Agenda | 必备第二页 | 必备（>8 条双列；>12 条自动分页） | 内容页 ≤4 可省 |
| 页头页脚 | eyebrow+标题+导语 | + so-what/来源行（仅关键页） | 极简（图例即页脚语义） |
| Exhibit 编号 | 不用 | **全篇连续编号 + 来源行** | 不用 |
| 引用密度 | 关键数字带 [n] | 关键数据 [n] + 文末参考资料 | 依据类 [1]–[3] |
| PPTX 正文字号 | 13pt | **10.5pt**（咨询密排比例尺） | 13pt（diagram 走全幅几何） |
| PPTX 页型组 | 通用 17 种（含 steps/heatmap/bullet/pyramid） | +5 密排专属（twocol/exhibit/threecol/halftable/matrix） | +lane（全幅 diagram/lane） |
| 典型篇幅 | 8–15 页 | 12–25 页 | 1–3 张图（6–8 页） |

**密度设计三原理**（为什么这样分）：

1. **A 投影契约**：一屏一主张 + 投影可读。留白服务可读，不是「删证据变疏朗」；主张页可用多卡/列表承载证据，装不下就拆跟进页。禁第二视觉重心（双大图、满屏小字墙）。
2. **B 高密度**：读者坐下来深读，视线按"F/Z 形"扫描页面，**单位版面的信息承载力就是生产力**——咨询机构的横向 A4 每页承载 600–900 字 + 一图/一表仍有呼吸感，靠的是行宽控制（34–40 字）、密排组件（Exhibit/密表/矩阵）与论证结构（每页标题即结论），而不是无差别缩小字号。
3. **C 图形密度**：评审场景读者要的是"结构在不在、链路通不通"，句子是噪音。文字退到图注级（≤400 字/页），图形密度拉满（节点 ≤24、图宽 ≥85% 版心），**1–3 张图即可成篇**——页数越少，评审越高效。

> **选错密度的典型症状**：A 出现双栏小字（投影看不清）→ 拆页或转 B；B 出现大面积留白 + 一句话页（坐读材料信息量不足）→ 合页或转 A；C 出现成段正文（图被文字挤压）→ 文字转图注或拆到 B 模式报告。

---

> **六项问询**（一次问完、全部带意图推荐、不选即按推荐走）：①意图与模式推荐合并确认（本表）②篇幅（A 8–15 页 / B 12–25 页 / C 1–3 张图共 6–8 页）③风格 9 套（始终选择——风格是 HTML 皮肤，与交付格式无关）④**亮暗主题**（浅色默认 / 深色沉浸；石墨深灰默认深色；HTML 与 PPTX 同主题导出——`REPORT_MODEL.theme`）⑤交付格式（仅 HTML / HTML+PPTX）⑥参考图确认（Gate 0 已展示整体图，问用户是否看到、要不要换）。载体优先结构化选项卡，宿主工具不支持则对话文本一次列全；问询顺序与完整措辞以 `SKILL.md` 为准。
>
> 六项问询收**形式参数**；模式确定后，内容主线/大纲/逐页规划走 `outline-design.md` 内容架构七步法（含按需大纲确认），再进入生成。

> **新页型适用模式**：`kpi` / `comparison` / `donut` / `quote` 四页型适用于 A 与 B（字段约束见 `scripts/model-schema.json`；HTML 版式见 `components.md` §39–42）。

## 模式 A · 演示汇报 `presentation`（assets/templates/presentation.html）

正式场合演讲演示文稿：优雅、大气、一屏一主张；3 秒抓住结论。工艺 → `presentation-craft.md`；默认面 → `default-surface.md`。**非**咨询密排 dump（那是 Mode B）。

要点回顾：

- **标题 = 主张/行动句**（action title），禁纯话题标签（「现状分析」等）；可短于 research，仍须是判断
- 字号大（正文 17–18px）、版心 1400px、band--fit 居中节奏、大气留白（休止页合法空 ≠ 内容页 underfill）
- 高度预算 1080p ≈ 830px；单页文字/单元预算是**溢出预警**（约 ≤1800 字 / ≤8 单元 / 表 ≤8 行）——**字多且结构合理（卡/列表）允许偏密**；超限先重构→拆页→换形态，**禁为疏朗删实质**（见 `presentation-craft.md` 长文节）
- **一屏一主张**：证据不够放时用次要卡/列表或**跟进页**，不砍 so-what / 证据
- 图表：8 核图优先；大而克制；简单图禁全幅；极偏禁 donut→V3；**motion = none**；多样性下限不变
- 主力版式 **V1–V4 / P1–P4 + P6/P10**；扩展 P5；**次级** P7–P9/P11–P12；advanced 图按需（不预读 extended）
- 节奏休止：连续数据页之间可插 1–2 处金句页（`components.md` §39，`band--accent`/`band--accent--solid`）；全文 1–2 处即可
- **收尾页用 `band--accent`**；`band--deep` 仅显式反相且不作末页（校验器检查）
- 交付：`--strict` 隐含 `--layout-qa`

## 模式 B · 研究报告 `research`（assets/templates/research.html）

> 对齐 McKinsey/BCG 咨询材料的密度与结构：**每一页标题就是结论（行动标题），正文是论证（发现→证据→含义），图表带编号（Exhibit），关键页有 so-what**。读者是坐下来深读的人，不是远看投影的观众——**更多文字、更高信息密度、更紧凑的空间布局**。

### 密度层（模板已内置，非运行时切换）

| Token | presentation | research |
|-------|-------------|----------|
| `--fs-body` | 17px | **14–15px** |
| `--fs-h1` | 48px | **34px** |
| `--fs-lead` | 21px | **17px** |
| `--wrap` | 1400px | **1240px**（阅读友好） |
| `--gap` | 16–28px | **12–20px** |
| band padding | 56–116px | **40–80px** |
| 表格行高 | 17px 20px | **13px 16px**（密度↑） |
| 表格行数上限 | 8 | **16**（密表） |
| 单页文字预算 | 1800 预警 | **3200** |

### 页面解剖（research：三必备 + 两按需）

```
[eyebrow]        02 · 现状诊断（章节编号+章节名）——必备
[行动标题]        结论句 ≥12 字（"六成企业试点卡在治理与集成——规模化分水岭已经出现"）——必备
[论证区]         锁定版式 R1–R8 之一——必备
[结论条]         .sowhat 一行收口（无 So what 标签 · MD3 衬条）——仅关键论证页加
[来源行]         .exhibit__src 随 Exhibit 组件自带；独立 .footnote 仅当页内有关键外部数据且无 Exhibit 时才加
```

> **克制条款**：不加多余的页头角标、chips 堆叠、逐页页脚信息行——咨询材料的信息密度来自论证结构与图表，不来自装饰性文字元素。

### 锁定版式 R1–R8（research 专属，不允许临场发明结构）

| 版式 | 结构 | 适用 | PPTX 页型 |
|------|------|------|-----------|
| **R1 论证页** | 行动标题 + `.cols-2` 双栏正文（发现→证据→含义 段落式）+ so-what + 脚注 | 需要完整论述的判断/逻辑推演 | `twocol` |
| **R2 Exhibit 页** | 行动标题 + `.exhibit` 图表框（编号+图+来源行）+ 右侧/下方 2–3 条解读 + so-what | 数据证据页（最常用） | `exhibit`（chart 支持 bar/hbar） |
| **R3 密表页** | 行动标题 + ≤16 行对比表（含结论列）+ so-what | 多维对标/清单 | `table` |
| **R4 指标带页** | 行动标题 + 4–6 指标卡一排 + 下方小表或迷你图 | 现状基线（兼作「半屏休止」节奏页） | `metrics` |
| **R5 分栏证据页** | `.g-side`：左宽（55%）论述，右窄（41.5%）Exhibit/表；也可反向（左图右文） | 证据+论证并置 | `split` |
| **R6 三栏证据页** | `.cols-3` 三栏短论证：三个并列论点 / 三方观点，每栏 ≤150 字 | 并列论点、三重门槛类结构 | `threecol` |
| **R7 半表半图页** | `.grid.g-half`：左密表 + 右 Exhibit（hbar/line），对照阅读 | 表图互证 | `halftable` |
| **R8 矩阵图页** | `.matrix`：rowHeads × colHeads 网格，强调单元 accent | 定位/优先级/象限判断 | `matrix` |

组件代码：`components.md` §36–36f。**切换组合规则**：每 3–4 页安排一个 R4 指标带页（防高密度疲劳）；R2 为默认主力版式；R6–R8 用于结构化对比类内容，让"更多内容、更紧凑布局"落在版式上而非字号上。

### 版式与内容规则（research 专属）

1. **行动标题**：`shead__title` 必须是结论句，不是主题词。eyebrow 改为章节编号+章节名。
2. **三段论证结构**：每页 = 发现（finding）→ 证据（evidence：表/图/数据）→ 含义（so-what：`.sowhat` 一行）。
3. **Exhibit 编号体系**：全篇连续编号（Exhibit 1、2、3…），放 `.exhibit__no`；`.exhibit__t` 写图表标题（结论式更好）；`.exhibit__src` 写来源行（组件自带）。**编号必须连续且唯一**（校验器检查）。文内引用写法："如 Exhibit 3 所示"。
4. **so-what 结论条**：`.sowhat`（accent 左边线 + soft 底），一行含义/建议，≤ 60 字；**只加在关键论证页**。
5. **双栏正文** `.cols-2`：长论述两栏排版，每栏行宽 ≈ 34–40 字；**三栏** `.cols-3`：并列短论点，每栏 ≤150 字。
6. **脚注式引用**：页内关键数据 `[n]` 上标；Exhibit 来源行走组件自带；**独立 `.footnote` 只在页内有关键外部数据且无 Exhibit 时才加**；文末仍有完整参考资料。
7. **更密的表格**：行数上限 8→16；允许 `--fs-xs` 的表格说明行。
8. **卡片可带 4–5 条列表**；并列单元上限 8→12；单页文字预算 1800→3200。
9. **左侧章节导航轨**：**默认不启用**；仅 ≥10 章深度白皮书且用户明确要目录常驻时才加 `.rail`（组件见 `components.md` §36c）。
10. 图表取尺寸下限即可（不必放大），但**不允许低于下限**；多系列图表常见（用 `f-c1~c5`）。

### research 模式的质量校验（validate_report.py 自动感知 data-mode）

- 单页文字预算 3200 / 单元 12 / fit 超载阈值 2200 / 表格行数 ≤16
- 行动标题检查：h1 级标题 ≥ 12 字（主题词式短标题 WARN）
- **Exhibit 编号连续性检查**（全篇 1..N 无跳号无重复；缺失 WARN）
- **so-what 连续性**：连续 >3 页无 `.sowhat`/`.note` → WARN
- **Exhibit 来源行**：每个 `.exhibit` 框内有 `.exhibit__src` → 否则 WARN
- **模式版式特征**：cols-2/cols-3/exhibit/matrix 至少一处
- 允许 `.cols-2`/`.cols-3`；分栏页的段落上限放宽（200 字/段）
- **图表多样性（v8 新增）**：全篇不同 `data-chart` 类型 ≥ `min(6, ⌈图表页数 × 0.6⌉)`；**相邻图表页不得同型**（阈值单源 `charts.variety`）
- **组合版式（v8 新增）**：含 ≥2 种承载类型（图表/表格/卡片/指标/图片/结构图）的内容页 ≥ **30%**——**单件页是例外不是默认**（组合矩阵见 `components.md` §46c 与 `references/playbook.md` §四）

## 模式 C · 信息架构图 `architecture`（assets/templates/architecture.html）

> 一页一张全幅主图，文字退到图注级别。**全文往往就一两张图或两三张图**——封面 + 1–3 张图 + 收尾即可成篇；内容页 ≤4 时**省略 Agenda**（校验器对 architecture 降为 WARN 提示）。受众：评审会/方案沟通，看结构不看句子。

### 密度层（模板已内置）

- `--wrap: 1600px`（更宽，图占满）
- band padding 压到 `clamp(32px,5vh,64px)`；正文/图表比例可到 2:8
- `.band--fit` 常用（图+图例正好一屏）

### 锁定版式 A1–A3（architecture 专属）

| 版式 | 结构 | 适用 | PPTX 页型 |
|------|------|------|-----------|
| **A1 分层带页** | 行动标题 + `.arch` 分层带（每层 = 层名条 + 节点卡网格）+ `.arch__conn` 层间连接 + 图例 chips | 系统/平台架构（最常用） | `diagram`（architecture 模式走全幅页型 fullStartY..fullEndY，含层间连接） |
| **A2 泳道页** | 行动标题 + `.lane` 泳道（角色/阶段为行，步骤横排+箭头）+ 图例 | 流程/职责/数据流 | `lane` |
| **A3 管线页** | 行动标题 + 全宽 SVG 流程管线（`fig--full` 内圆角横条+流向箭头）+ 图注 | 端到端链路 | `lane`（单泳道五步管线映射） |

组件代码：`components.md` §37–38b。A1 默认；强调跨层流转用 A3。

### 图示组件库（components.md 第 37–38b 节）

- **分层带** `.arch`：横向分层（应用层/编排层/模型层），层内放节点卡——架构图最常用
- **节点卡** `.arch__node`：圆角小卡（标题+一行注），支持 accent 强调焦点节点
- **层间连接** `.arch__conn`：层与层之间的垂直短箭头（主链路 accent、次链路中性）
- **泳道** `.lane`：行 = 角色/阶段，`lane__step` 步骤横排 + `.lane__arr` 箭头
- **正交连接件**（SVG）：主链路 `.s-acc` 实线 2px、次链路 `.s-bds` 虚线 1.5px；箭头三角 `f-txt3`/`f-acc`
- **图例 chips**：右下角一行（焦点层 / 已有能力 / 主链路 / 数据流）

### 结构图形族（复杂架构图 / 流程图 · 图为王时的主力）

> `.arch` / `.lane` 只覆盖**分层**与**线性步骤**；一旦内容含**分支、判断、汇合、异常路径、层级、时序、闭环**，就必须用结构图形——否则会退化成"矩阵方块 + 文字箭头"（`failure-modes.md` F13）。
> 规范与可复制 SVG 见 `infographics.md` §78–§82；PPTX 侧映射 `diagram`（分层/层级）或 `steps`（时序/闭环）页型，分支与例外写入 `note`（进演讲者备注）。

| 结构图形 | 用什么 | 上限 |
|---------|-------|------|
| 流程图 `flow` | 动作=圆角矩形、判断=菱形、异常=虚线；分支标条件、正交路由、汇合总线 | 节点 ≤20 / 判断 ≤4 |
| 层级树 `tree` | 父→子正交连接 + 同层等高；层级靠明度阶梯 | 叶 ≤16 / 深 ≤4 |
| 时序图 `sequence` | 参与者 + 虚线生命线 + 消息箭头 + **激活条** | 参与者 ≤5 / 消息 ≤8 |
| 闭环 `loop` | 方向一致的箭头 + 中心结论（箭头是主角） | 环节 ≤6 |

**判据**：内容里出现「A 流向 B」「要走哪个分支」「谁先谁后」「上一层下一层」「转一圈回到起点」→ 用结构图形，不要用文字箭头或并列卡片冒充。

### 内容规则

1. 每页**只放一张主图**；图宽 ≥ 版心 85%；高度预算 500–700px
2. 文字只允许：eyebrow + 行动标题（≤20 字）+ 图注（1–2 行）+ 图内节点短标签（≤8 字/节点）
3. 节点数上限：分层图 ≤ 24 个节点、泳道每行 ≤ 6 步、流程 ≤ 10 步；超出拆页
4. 层次用 surface 明度差 + accent 高亮"当前焦点层"，不引入第二色相
5. 图内文字最小 11px；连接线 1.5–2px；正交折线优先于斜线
6. 图例必须与图内语义一一对应
7. **可省略 Agenda**：内容页 ≤4 时封面后直接进图；页多（≥5 内容页）建议补
8. 长说明全部转图注或拆到 research 模式报告；图为王，文字退到图注级

## 复杂信息图页型族（research / architecture 可用）

> 完整规范见 `references/infographics.md`；HTML 写法见 `components.md` `infographics.md` §71–§77。**判据**：普通图表回答"一个数是多少"，信息图页型回答"一整套结构长什么样"。

| 页型 | 承载什么 | 上限 | 适用模式 |
|------|---------|------|---------|
| `sankey` | 多主体之间的**流向与流量**（转化链路、资金流向） | 节点 ≤12 / 流带 ≤24 | research / architecture |
| `treemap` | 层级构成 + **面积编码**（区域收入、成本结构） | 叶节点 ≤16 | research / architecture |
| `boxplot` | 分组**分布**（中位/四分位/极值/离散度） | 组数 ≤8 | research / architecture |
| `network` | 节点-边**拓扑关系**（系统依赖、协同链路） | 节点 ≤18 / 边 ≤30 | research / architecture |
| `marimekko` | **双重编码**（列宽 = 总量、列高 = 构成） | 列 ≤6 / 段 ≤4 | research / architecture |
| `streamgraph` | 时间上的**构成演变**（结构此消彼长） | 系列 ≤6 | research / architecture |

**共用纪律**：见 `infographics.md` §二（通用铁律 10 条：每页一图、采样点下限、双边界追踪、量级线性编码、数据可追溯、上限硬约束、配色克制、文本退图注级）。超上限按铁律 11 **拆页**（结构容量问题，缩字号无效）。

**模式适配**：
- **research**：信息图页作为"证据页"承担一整个论证环节，必须配行动标题 + `.exhibit__src` 来源行；密集报告里信息图页与密表页交替出现（节奏）。
- **architecture**：信息图页是"图为主角"的自然延伸，页头更简（可省导语），节点标签允许更短（≤6 字）。

## 模式 × 风格 × 导出的关系

- 模式影响：独立模板骨架、密度 token、内容规则、页面预算、图表尺寸策略、PPTX 页型与**独立排版比例尺**（`layout-constants.json` `modeTypeScale`：research 咨询密排正文 10.5pt，非简单 ×0.8 缩放）
- 风格影响：色彩/字体/圆角/阴影（9 套任选，research 推荐 mckinsey/warm-sand/deep-teal，architecture 推荐 graphite-dark/business-blue/spectrum）
- 导出：`REPORT_MODEL.mode` 随报告记录；PPTX 按模式分派页型（research：twocol/threecol/exhibit/table/metrics/split/halftable/matrix + 密排比例尺；architecture：diagram 全幅/lane，**无 agenda 时少一页大纲**）
- 校验：`validate_report.py` 读 `data-mode` 自动切换预算阈值与版式断言；`validate_pptx.py --model` 按"有无 agenda"断言页数结构；模式未声明按 presentation 处理并 WARN
