# 内容规则（面向演讲演示 · 去AI味 · 密度高效）

> **何时读**：写正文、调密度、去 AI 味、处理引用与待核实标注时。**何时不读**：定模式/选版式阶段（用 `playbook.md`）。
> **取节**：`python scripts/extract_snippet.py --task content-rules`（密度/字数/去AI味打包）。整读 30KB 视为浪费。
> **目录**：一 文字 · 一-b 图标 · 一-c 彩色 · 二 去AI味 · 三 数据化 · 四 密度 · 四-b 复杂布局 · 四-c 溢出处置（禁截断） · 四-d 丰富度分级 · 四-e 细节保全 · 四-f 表格字号与内边距 · 五 引用 · 五-b 待核实 · 六 章节骨架 · 六-b Mode A 主张标题 · 七 交付自查 · 八 research 规则

## 核心判断标准（v8：先保全，后呈现）

**第一步不是"删"，而是"定"**：先问 **"这条信息是决策必需的吗？"**
- 是 → **必须进主页面**——再想用什么形态承载它（文字 → 列表 → 表 → 图 → 组合版式）。
- 不是，但需要可查 → 沉图注 / 来源行 / 附录。
- 都不是 → 才允许删。

**第二步才是"简"**：形态定了之后，问 **"如果我在台上讲这一页，观众 3 秒内能抓住什么？"** 抓不住 → **换承载形态或调版式**，而不是删掉决策必需的信息。

> **research 模式**：判断标准换成 **"读者 30 秒内能否读完这一页的论证？"**——行动标题是结论、论证区是证据、so-what 是含义。密度规则见第八节。
> **两条禁令（"内容丢失"的根因）**：① 禁止为排版方便砍口径列 / 时间列 / 维度；② 禁止用"抓不住就删"直接砍掉决策必需的信息。

## 一、文字：短、断、可念（结构优先 · 禁为疏朗而删）

> **反截断**：下列是**结构引导**，不是「超字数就删掉」的硬砍刀。长文先列表化 / 拆卡 / 拆页，**禁止**静默截断或丢掉 so-what / 证据。详规见 `presentation-craft.md`「长文与信息承载」。

| 位置 | 结构引导（非删除许可证） |
|------|------|
| 章节导语（lead） | 宜 ≤2 行；超长 → 拆成导语 + 列表，或挪到下一页主张页 |
| 卡片内正文 | 纯段落宜短；**超过约 3 行 → 转列表 / 拆成多卡**，勿压行删义 |
| 单句长度 | 宜断句（约 40 字换气）；超长 → 断句或分条，勿删判断 |
| 单个列表项 | 宜 1–2 行可读；证据句可略长——放不下就**加行/拆项/拆页**，勿截断加省略号充数 |
| 一屏核心主张 | 只能有 **1 个**；证据可用次要卡/列表/跟进页承载 |

句式：主动句；数字前置；结论前置；把长定语拆成并列。

**✗ 单句超长（48 字，读者换气即丢失）**
> 通过对三家试点企业在过去两个季度中沉淀的调用日志进行回溯分析，我们发现工具链完备度与规模化成功率之间存在显著的正相关关系。

**✓ 断句改写（结论前置 + 数字前置）**
> 工具链完备度正相关规模化成功率——基于 3 家试点企业、两个季度的调用日志回溯。

### 段落 → 列表 的转换

**✗ 反例（大段，不适合演讲）**
> 传统数据治理把数据当作需要看守的资产；DGIG 把数据当作能够自我增强的生产资料。治理动作本身产生更高质量的数据，更高质量的数据喂养更聪明的 Agent，更聪明的 Agent 带来更好的业务结果，业务结果又生成新的数据，形成正反馈闭环。

**✓ 正例（列表化，可扫读可讲述）**
```
传统治理：数据 = 需看守的资产
DGIG：    数据 = 能自我增强的生产资料
闭环链路：
→ 治理动作产出更高质量数据
→ 高质量数据喂养更聪明的 Agent
→ 更聪明的 Agent 带来更好业务结果
→ 业务结果生成新数据
```

## 一-b、图标：克制而合理（不是很少，更不是没有）

图标是**信息的路标**。用对位置能显著提升可扫读性；滥用则变成新噪音。

- **四个正当位置**：卡片头（`.card__ico`）、关键列表行首（`.ul--ico`，3–5 条的关键列表最值得加）、指标卡角标（`.metric__ico`）、提示条（`.note__ico`）。
- **不用**：Agenda、表格内、图表内部、正文行内。
- **密度**：每屏 3–8 个；连续两三屏零图标时，给要点卡补一个。
- **一致性**：只用描边风（icons.md 全套），stroke 1.8，`currentColor` 不改。
- 图标库与语义速查：`references/icons.md`。

## 一-c、彩色（编码色 · 9 套风格通用）

- 彩色**只**属于数据：图表系列、图例色点、小段标签。结构（标题/正文/边框/按钮/大底色）永远中性。
- 多系列图表一律用 `f-c1~c5` 语义类——**9 套风格各有自己的 5 色板**（单源 `styleDataColors`，随主题切换），代码不用改。
- 同屏彩色系列 ≤ 5；标题、大数字、强调卡**不**用彩色。

## 二、去AI味（交付前必过，逐条替换）

> 源自《AI 写作特征》（Wikipedia:Signs of AI writing），收敛为商务报告场景。
> **目标：像懂行的人在讲，而不是 AI 在念稿。**

### 立即删除/替换的高危痕迹

| AI 腔 | 改成 |
|-------|------|
| 赋能、抓手、颗粒度、闭环（堆砌时） | 说清具体动作，如"把口径统一到指标中心" |
| 彰显、凸显、见证了、标志着 | 直接陈述事实 |
| 至关重要、深刻的、宝贵的 | 删，或用具体数字 |
| 格局、生态、体系（空泛） | 说清是哪一层、谁和谁 |
| 不仅…而且…、不是…而是…（连用） | 只留一半，直接说结论 |
| 随着…的不断发展、在…的背景下 | 删掉开头，直奔主题 |
| 大幅提升、显著改善、质的飞跃 | 用数字，如"使用率 31%→60%" |
| 行业报告显示、专家认为、有相关人士表示 | 给具体来源，或删掉 |
| 令人叹为观止、充满活力、丰富的 | 删，商务报告不用形容词堆砌 |
| 无缝、极致、一站式（宣传语） | 说清具体能力 |
| 未来可期、迈上新台阶、开启新篇章 | 给下一步具体动作 |

**✗ AI 腔整句（命中 4 个高危词）**
> 随着数字化浪潮的不断发展，该平台无缝赋能企业核心场景，标志着行业迈上新台阶，未来可期。

**✓ 改写（删填充、给事实）**
> 平台已接入 12 个核心场景；下一季度补齐审批链路，覆盖至 20 个。

### 结构性 AI 痕迹

- **填充短语**："为了实现这一目标"→"为此"；"在这个时间点"→"现在"；"值得注意的是"→删。
- **三段式堆砌**：强行凑三点显得全面 → 两点或四点更自然。
- **破折号过度**：一屏最多 1 处破折号。
- **粗体过度**：一句里粗体不超过 1 处；整屏粗体克制。
- **-ing 式肤浅分析**（中文："…着其重要性""…中发挥着关键作用"）→ 删尾巴，直接说作用是什么。
- **通用积极结尾**："前景广阔、值得期待"→ 换成具体下一步。
- **过度限定**："可能会在一定程度上潜在影响"→"可能影响"。

### 保留人味（别改到无菌）

- 长短句混合，别每句一样长。
- 可以有明确判断："这一步最关键""这里风险最大"。
- 承认不确定："这个数字还没实测，先标 `xx`"。
- 别像新闻稿。允许一两句口语化但不失专业的话。

## 二-b、引用与模型字段（防标签泄漏 · 硬纪律）

- **HTML 正文**：外部数据用 `<a class="cite" href="#ref-n">[n]</a>`。
- **REPORT_MODEL 字段**：只写纯文本；引用写 `[n]`。**禁止**把 `<a class="cite">` / `<strong>` 等标签写进模型字符串——会在 PPTX 原样露出（门禁 `HTML_TAG_IN_TEXT`）。
- 表格单元格、要点、soWhat、footnote 同理：模型纯文本，样式由引擎渲染。
- **单写路径**：优先只改模型，再用 `render_from_model` 的 `--inplace` 生成正文；不要手工同步两份。

## 三、数据：能图表化就不文字化

| 数据类型 | 用这个 | 不要用 |
|---------|-------|--------|
| 占比 / 构成 | 环形图 / 堆叠条 | 一句话文字 |
| 时间趋势 / 分阶段目标 | 柱状图 / 折线 | 表格 |
| 多维对比 | 对比表 | 两段文字 |
| 流程 / 架构 / 闭环 | 内联 SVG 图 | 编号列表 |
| 时间计划 | 时间线 | 表格 |
| 单值重点 | 大数字 + 一行注 | 段落 |
| 现状基线（并列指标） | 指标卡 | 列表 |

**✗ 数据文字化（占比藏在句子里，读者无法比较）**
> 其中工具类占比 42%、资讯类占比 31%、社交类占比 27%，工具类优势明显。

**✓ 数据图形化**：`donut`（扇区 3 个，条目数值标环内/条末，来源行写口径）——比较交给眼睛，文字只留"工具类领先 11 个百分点"这层含义。

图表实现（纯 SVG，无库）：环形图、条形图、柱状图等 36 种图表做法见 `charts.md` §16–§31、§35、§52–§70；桑基/树图/箱线/网络/马赛克/流带六类**信息图页型**见 `infographics.md` §71–§77。

## 四、信息密度与空间利用（合理高效）

**目标：充实但不拥挤，留白但不空旷。**

### 密度基准（建议量 · 超限先改结构）

| 元素 | 结构建议 |
|------|--------|
| 每屏并列单元（卡片/图/表） | 演示宜 ≤8（research ≤12）；更多 → **拆屏或改表**，勿删条目凑数 |
| 单卡片列表项 | 宜 3–5 条；更多 → 拆卡 / 两组 / 跟进页，**勿截断条目文字** |
| 单卡片正文 | 纯段落宜短；长论证 → 列表化或多卡，不靠删句疏朗 |
| 指标卡一屏 | 4–6 个 |
| 表格一屏行数 | ≤8 行（research 密表 ≤16）；超限 → Top N + 附录全表 |
| 单个列表项 | 宜可读完整；投影场景避免墙式长句，但**完整证据优先于字数帽** |

### 空间利用

- **避免大面积空白**：卡片内容太少时，减少卡高或改 2 列为 3 列；不要为凑满栅格留半空卡（半空与塞爆**同样不合格**）。
- **避免塞爆**：并列单元超上限 → 分两屏 / 改密表；列表过长 → 拆组或跟进页——**提炼≠删除决策必需信息**。
- **Mode A 密度许可**：主张清楚时，卡片/列表页允许偏密；一主张可带充分证据卡，证据装不下就加页，不砍 so-what。
- **留白节奏**：章节上下留白一致（`clamp(56px,8.5vh,116px)`），栅格间距一致（`clamp(16px,1.6vw,28px)`），卡片内边距一致（`clamp(20px,2vw,30px)`）。
- **对齐**：同类元素左对齐同一轴线（共享左缘/顶边）；数字列右对齐或 `tabular-nums`；标题与正文左缘对齐；列节奏跨页稳定。

**✗ 塞爆（一屏 10 卡 × 每卡 6 条，投影不可读）** → 拆两屏各 5 卡，或 10 卡压成一张 `table`（research 密表 ≤16 行）。
**✗ 半空卡（2 条内容占 4 条的卡高）** → 减卡高或改 2 列为 3 列，不留"凑数卡"。
**✗ 为疏朗而截断**（条目末「…」、证据消失、so-what 被砍）→ 按 §四-c 重排/拆页，禁止静默丢内容。

### 一页好报告的观感

> 远看清结构（几栏、几个色块），近看有内容（每格都言之有物），没有半空的卡，也没有密不透风的墙。

## 四-b、复杂页面布局（图 + 文 + 卡混排）

一个页面同时有图表、文字、卡片时，按"**先定主次，再定栅格**"处理。

### 九种经典版式（优先套用，完整代码见 `components.md` 第 32–34、43–45、47–50 节）

> **新增栅格（同属"先定主次"工具，见 `components.md` §46b）**：三栏非对称 `g-211`/`g-121`、四象限 `g-quad`、粘性侧栏 `g-aside`、命名区马赛克 `g-mosaic`/`g-hero-full`、等高行 `rows-2/3`、双列键值 `kv--2col`——在九种经典版式不够用时优先从这组里选，**仍禁止临场发明结构**。

1. **左图右文 / 左文右图（`g-side`）**
   - 主图占 1.3 份，文字/清单占 1 份。适合「一个大图 + 一组解读」。
   - 图放视觉重心侧（通常左或上），文字做 3–4 条列表解读。

2. **上图下卡**
   - 顶部一个通栏图（架构图/趋势图），下方 3–4 张并列卡片做分解。
   - 适合「总体架构 + 分层拆解」。

3. **指标带 + 主图**
   - 顶部 4–6 个指标卡一条带，下方一个主图或主表。
   - 适合「现状基线 + 聚焦分析」。

4. **表 + 图并排（`g-2` 顶边对齐）**
   - 一侧图、一侧小表，互相印证。适合「结论 + 证据」。
   - 表行数 ≤5；高度差大时矮侧补一张注解卡。

5. **2×2 卡图混排（四象限，`g-2`）**
   - 图与卡对角分布。适合「四个并列观察」。
   - 这是单屏密度上限，再多就拆页。

6. **全幅图表页（`fig--full`，`components.md` §43）**
   - 一个图撑满整页（宽 ≥ 版心 90%），标题结论 + 图注收口。
   - 适合「单图信息量大、需要全场聚焦」：架构总览 / 全景趋势 / 复杂管线。

7. **里程碑时间线页（`tl`，`components.md` §44）/ 指标墙页（`g-6` metrics，`components.md` §45）**
   - 时间线：3–5 个里程碑叙事，每个 ≤2 行（排期任务条用甘特，勿混）。
   - 指标墙：6±2 个指标一排 + 口径行收口；单个核心数字压场改用 kpi 版式。

8. **步骤条页（`.steps`，`components.md` §47）/ 热力矩阵页（`.heat`，`components.md` §48）/ 达成对比页（`.bul`，`components.md` §49）/ 金字塔页（`.pyr`，`components.md` §50）**
   - 步骤条：实施节奏 / 操作流程 3–6 步，每步「动作 + 一句说明」；关键步 `.step--a` ≤2 处。
   - 热力矩阵：二维强度对标（行业×场景等），4 级色阶**只用强调色明度阶梯**；行列 ≤5×5，超了拆附录。
   - 达成对比：实际 vs 目标，目标线标在条上，未达标行转中性色（**不用红绿**）。
   - 金字塔：层级递进 3–5 层，自上而下逐层加宽，强调层 ≤1。

9. **拼贴页（`.g-bento`，`components.md` §46b）/ 交错图文页（`.stagger`）/ 键值对照（`.kv`）/ 素材图片族（`.media*`，`components.md` §11c）**
   - 拼贴：一屏 4–7 个**不等大**单元（主卡跨 2 列/2 行），适合经营快照 / 能力矩阵；单格宜短（约 3 行）；更长 → 拆格或跟进页，勿截断。
   - 交错图文：3–4 组「图 ↔ 文」交替，一组只说一件事；比左右分栏更有节奏，但**组数 ≤4**（多了变流水账）。
   - 键值对照：≤6 组，适合口径/参数/对照项的轻量表达，比表格省空间。
   - 素材图片（`components.md` §11c）：**六版式**按内容选——单张实拍/横幅用 `full`（3:1）｜图文互证用 `half`（左图右注，注解 3–4 条）｜章节情绪页用 `bleed`（21:9）｜多张并列互证用 `grid`（2/3/4/6 张，4:3）｜前后/方案对照用 `compare`（恰好 2 张 + A/B 角标）｜客户生态用 `wall`（Logo 墙）。
   - **一屏一视觉重心**：主图宽 ≥ 版心 55%，图与文顶边对齐；图注写清口径与版权（`.media__cap--below` + `.media__src`）；**多图并列页不要连着两页堆**（属节奏页，用于章节过渡或证据页）。
   - **没有素材图不要省略图，也不要塞无关图**：用配图占位（`.media--ph` + `image.placeholder`）把版式、比例、图注位置一次锁死，交付前替换 `src` 即可（`components.md` §11c-3）。占位必须带 `.media__ph` 标签（图标 + 配图占位 + 建议尺寸）。
   - **数据图不要用截图**：折线/柱状/占比一律用内联 SVG 图表（`data-chart`），才能随主题变色并过图表登记校验。

### 混排规则

- **一屏只一个视觉重心**：要么图最大，要么数字最大，别让图、表、卡都一样大互相打架。
- **图要够大**：主图宽度不低于版心 55%，环形 ≥140px、柱/折线 ≥200px 高、雷达 ≥220px；**宁可减少图的数量，不要把图缩成一团**。
- **文随图走**：图的旁边/下方配 3–4 条列表，而不是大段文字。
- **对齐**：图与卡片的顶边对齐、左缘对齐；多图并排时等高。

## 四-c、内容过多怎么办（溢出铁律 · 禁止静默截断）

> **用户硬原则**：Lots of text **must NOT** be deliberately compressed or deleted just to look like a sparse demo deck. 优先合理卡片、列表、分节、换形态、多页分解。

一页放不下时，按**此顺序**处理（高度预算见 `design-system.md` §1c；常量 `containers.overflowRule`）：

1. **重构承载**：段落 → 列表 / 卡片 / 表 / 图 / 组合版式。**同一份信息换形态，不丢掉。**
2. **拆页 / 分章**：追加页、01a/01b、多部分章节；推荐序列 **议程 → 主张 → 证据卡 → 明细列表**（`recommend_layout` 高容量意图会建议多页）。拆页须信息完整（续表 / 附录 / `note` 交代）。
3. **换布局形态**：V1–V4、多列、卡栅格、`g-side` / `g-bento` / `rows-2/3`；单件改组合页（主件+从件+注释层，`playbook` §四）。
4. **有限 `fontShrink`**：仅在 1–3 步之后；最多 4 档；floor presentation/arch 10pt、research 9pt。
5. **禁止**：静默截断（省略号充数）/ 砍 so-what / 砍证据与口径列 / 为「看起来疏」删决策必需信息。**精简只允许删决策非必需项，且永不作为第一步。**

**禁止**：① **无限**缩字号硬塞；② 内容越出页面或归属容器被裁；③ 把"精简/压缩"当第一手段；④ **溢出却不拆页**（校验 `LAYOUT_QA_OVERFLOW_NO_SPLIT`）。
**单页字数预算**（`checkBudgets.char`）是预警与结构提示，**不是**「字多→删字」许可证；字多而结构合理（卡/列表）的 Mode A 页允许偏密。

> 反向情况——内容明显不足一屏且接近满屏观感更好时（Hero/Agenda/收尾章/大指标页），给该页加 `band--fit` 垂直居中，避免"上半页挤、下半页空"。

### Agenda = 章节大纲（3–7 章，不是页目录）

- **条目 = 章（篇 / section），不是页**。每章含 1+ 页；页标题逐页出现，章标题只在 Agenda 出现一次。
- **条数预算：3–7 章**（演示 3–5 章；研究 4–7 章；含「参考资料」条目时 +1，仍 ≤8）。
- 章标题 = 该章结论（行动句），一句话说明 = 该章关键证据预告（`outline-design.md` ⑤）。
- **出现 8 条以上 = 你在列页**：按 eyebrow 章前缀（如 `01 · 范式`）归并回章；禁止把逐页标题当大纲。
- 排版：≤8 条单列；仅当章节化后仍 >8（异常）才 `.agenda--2col`。PPTX 自动分页只是安全网，不是设计目标。
- 跳转锚点 = 该章第一页；校验器查锚点与章标题闭环。
- 单条标题 **≤36 字**（`titleMaxChars`）：超长截断、全称沉演讲者备注。

## 四-d、内容丰富度分级 → 版式与节奏

> **不同页的内容量不一样，版式就不能一样**。先给每页定密度档，再按档选版式——禁止"一个版式套全篇"。
> 密度档判断以**该页并列信息单元数**（卡片/指标/图/表列）为主，文字量与图表数为辅。

### 三档判定与对应版式

| 密度档 | 判定（presentation 基准） | research 基准 | 首选版式（密度从低到高） | 排版参数 |
|-------|--------------------------|--------------|--------------------------|----------|
| **L 轻**（单主张页） | 1–2 个单元；或一个核心数字/金句/结论 | 一个 Exhibit + 一行 so-what | kpi 大数页（`components.md` §41）/ 金句页（`components.md` §39）/ D 全幅图表（`components.md` §43）/ 环形图页（`components.md` §42）/ 金字塔（`components.md` §50） | 垂直居中（默认页高模型）；字号走上限（h1/display）；图表取大尺寸 |
| **M 中**（标准页） | 3–4 个单元 | 双栏论证 R1 / 半表半图 R7 / 对比页 | g-2 / g-hero / g-hero--rev / g-side / g-side--rev / g-31 / g-13 / g-41 / g-14 / comparison（`components.md` §40）/ 步骤条（`components.md` §47） | 标准字号与栅格 gap；主次分明（非对称栅格优先于均分 g-2） |
| **H 重**（密集页） | 5–6 个单元（research ≤12） | 三栏 R6 / 密表 R3 / 矩阵 R8 / 指标带 R4 / 热力矩阵 `components.md` §48 | g-3 / g-4 / g-5 / g-6 指标墙（`components.md` §45）/ 表格（`components.md` §7/8）/ R6 三栏 / heatmap（`components.md` §48）/ bullet（`components.md` §49） | 字号走下限但仍达标；贴顶（`.band--top`）；单元数超上限先拆页 |

### 版式与密度匹配的硬规则

1. **轻页勿空、重页勿爆**：L 档页内容接近一屏即可（页高模型默认居中撑满）；H 档页超预算按「四-c 先减后拆」处理，**禁止**用 L 档版式硬装 H 档内容（溢出）或用 H 档栅格装 L 档内容（半空卡）。
2. **非对称优先**：主次分明的 M 档内容（一图一解、一结论一证据）用 `g-side` / `g-31`（图/结论占大），而不是均分 `g-2`；镜像场景用 `g-side--rev` / `g-13`。
3. **页间节奏**：连续两页同为 H 档 → 中间插一个 L 档休止页（金句/大数/全幅图）；research 每 3–4 页一个 R4 指标带页做呼吸（既有规则，与三档节奏一致）。
4. **模式叠加**：architecture 模式恒为"图为王"（L 档文字 + 高图形密度），本节三档只作用于文字与附属图注；research 的 H 档上限高于 presentation（见上表基准列）。
5. **选完版式回查**：对照 `components.md` §46 内容形态表核对页型映射，确保 HTML 版式与 PPTX 页型同源。

## 四-e、细节保全（数据/细节密集页）

> 完整策略见 `outline-design.md` §二（承载工具选型矩阵 + 超限拆分流程 + 信息图三原则）；本节是页内执行要点。

- **每条细节有去处**：决策必需 → 主页面；可查证 → 图注/来源行/附录；都不影响 → 删。**禁止砍列保版式**（口径列/时间列不许砍）。
- **承载形态升级优先于拆页**：文字列举 → 密表；表 → 图（矩阵→散点、清单→密表）；多维对比 ≥3 对象 × ≥4 维必用表。
- **超限拆分**：表 >16 行 → 主表 Top N +「其余合并」行 + 文末附录全量表（同源同口径）；指标 >6 → 指标墙 + 附录明细。
- **图注沉淀**：图中放不下的条件/例外/口径沉 `.fig__cap` / `.exhibit__src` / `.footnote`（≤1 行/处），不在图周围加大段文字。
- **数据标在图上**：关键数值标在数据本体旁（条末/点侧/环内），不强迫读者查图例换算；单位与口径写来源行。
- **自查反模式**：✗ 20 行表拆成 20 个卡片（不可比）；✗ 表旁文字复述表内数字（文字只写表不能表达的：趋势/对比/含义）；✗ 图做小、细节在长文（图是主角，文字是解读）。

## 四-f、表格语义字号 · 容器内边距 · 连续文本流

> 语义字阶定义见 `design-system.md` §1f（C0–T14）；容器内边距常量见 `layout-constants.json` `containers`；本节是**写作与排版时的执行纪律**。

### 表格语义字号（按内容性质选层级，不是按"能不能塞下"选）

| 表格内容性质 | 允许层级 | 说明 |
|-------------|---------|------|
| 表格正文、行动项、风险项、解释句、建议句、长项目符号、完整短句 | **T7 或 T10**（`body`） | 句读型内容——必须可读，不得降级 |
| 轴标签、刻度、图例、单位、列短标签（≤4 字）、非句子型微标签 | **T11**（`micro`） | 仅限标签型，**禁止**用来放句子 |
| 表头 / 首行 | 与表格正文同级或高一档（`bold` 加粗表达层级，**不靠放大字号**） | 表头不得比正文小 |

**硬纪律**：
- **禁止**用缩小字号换取"表格装得下"——放不下按 §四-c 先减后拆（砍列前先精简文字 / 换承载形态 / 拆页）。
- **表格密度必须与内容匹配**：字号未低于下限但单元格大面积空洞、阅读重心塌陷、页面显空，同样判不合格（`validate_pptx.py` 的表格密度检查）。
- 数值列右对齐 + 等宽数字（`tabular-nums`）；单位统一写在表头（如「金额（亿元）」），不在每个单元格重复。

**✗ micro 装句子（T11 放 26 字解释句，投影即不可读）**
> `<td class="t-micro">该指标受季节因素与促销节奏双重影响，环比波动属正常区间</td>`

**✓ 语义分级**：解释句用 `body`（T7/T10）；`micro` 只放「QoQ」「亿元」这类 ≤4 字标签。放不下按 §四-c 先精简再拆页，不降字号。

### 容器内边距（文字溢出按"归属容器"判定）

- **判定单位是容器，不是页面**：文字 / 关键数字 / 项目符号 / 图表标签 / 来源说明不得越过**归属容器**边界（卡片 / 面板 / 图表区 / 单元格 / 结论条 / so-what / 标题区 / 页脚区 / KPI 框）——**即使没有超出页面画布，只要越过归属容器即失败**。
- 每个容器必须保留**可见内边距**（下限见 `layout-constants.json` `containers.pad`；`minPad` 为绝对下限）。
- 溢出处置：① 列表化/精炼 ② 调整容器尺寸 → 收窄行宽 → 换行 → 分区 → 拆页 ③ **有限缩字号**（`fontShrink`）。禁止无限缩字号替代结构重排。
- 卡片内边距 ≥ 组间距；标题与其正文的间距 **小于** 组与组之间的间距（CRAP 的 Proximity）。

### 连续文本流（不要为高亮而拆文本框）

- **语义连续的一句话 / so-what 主句 / 结论句 / 表格单元格正文不得拆成多个独立文本框**——会产生异常空格、断句、基线漂移、位置错位。
- 需要局部加粗/变色高亮时，用**同一文本框内的富文本**（HTML 用 `<strong>`；PPTX 用同一 `addText` 的多 run），不得另起一个文本框。
- 数字 + 单位 + 括号注释属于同一语义单元，不得拆开排版。

### 跨页叙事节奏

单页合格 ≠ 全篇好看。规划完成后按 `outline-design.md` §一-续 回查：密度交替（禁连续 3 页同密度）、章节色彩递进、首尾呼应、渐进揭示、两个视觉重心禁令。

## 五、引用：外部数据必标 `[n]`

1. **外部数据、行业预测、他人研究** → 数值后加 `[n]` 上标。
2. **内部实测** → 标来源与日期，**不加** `[n]`。
3. **推算 / 待确认** → 显式标注口径，或用 `xx` 占位。
4. **「参考资料」只列真实来源**：
   - 材料/正文引用了真实来源（报告名、机构、文档、URL、内部调研名）→ 列条目：`[n] 来源名（机构），时间；口径；链接（如有）`。
   - **没有真实来源 → 整节省略**（并删正文 `[n]`/`.ref-link`；导航与收尾的「参考资料」入口一并去掉）。
   - **禁止占位条目**：「来源名称，时间；口径。」「来源 N（替换为真实来源名称）」「某行业报告」等模板串一旦出现在交付物即 FAIL——宁缺毋假，不得误导读者以为存在可追溯来源。
   - 无外部引用但需交代内部口径 → 用各页 `.footnote` / `.exhibit__src` / `.media__src`，不设空的「参考资料」页。
5. **来源带链接的保留链接效果** —— 外部 URL 或可追溯的内部文档，来源名做成可点击链接 `<a class="ref-link" href="…" target="_blank" rel="noopener">`，新窗口打开；无链接来源保持纯文本。

**✗ 无效引用**：① 正文 `[3]` 但文末只有 2 条（编号错配，校验 FAIL）；② 条目只写「某行业报告」（无时间无口径，不可追溯）；③ 内部实测也挂 `[n]`（应标「内部实测 · 2026-08」）；④ 条目是「来源名称，时间；口径。」占位串（交付物出现即 FAIL）。

上标样式与参考资料章节代码见 `components.md`；`.ref-link` 样式见 `design-system.md`。

### `.ref-link` 用法

```html
<td><a class="ref-link" href="https://www.gartner.com/en/newsroom" target="_blank" rel="noopener">
  Gartner：Agentic AI 技术成熟度曲线
  <svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"
       stroke-linecap="round" stroke-linejoin="round">
    <path d="M18 13v6a2 2 0 0 1-2 2H5a2 2 0 0 1-2-2V8a2 2 0 0 1 2-2h6"/>
    <path d="M15 3h6v6M10 14 21 3"/></svg></a></td>
```

外链用完整 `https://…`；同目录内部文档用相对路径（如 `2026-08-26-….html`）。

## 五-b、待核实标注：需要用户二次修改的内容用强调色标出来

> **原则：标色 = 行动项。** 凡是**你无法核实、需要用户确认或替换**的内容，必须用强调色标出来——否则用户会默认它是已核实的结论，带着错误数字交付出去。

### 什么时候标（三类）

| 类型 | 例子 | 标注 |
|------|------|------|
| **无法核实的数字** | 外部预测值、口径未定的百分比、估算量 | `<span class="tbd">xx%</span>` 或 `<span class="tbd">约 1,200</span>` |
| **待确认的判断** | 成熟度评级、时间窗、"领先/落后"结论 | `<span class="tbd">早期验证</span>` |
| **待替换的占位** | 品牌名、项目代号、未定稿的排期 | `<span class="tbd">待定</span>` |

### 三种载体（由轻到重）

1. **`.tbd` 内联** —— 标在数字/短句本体上（accent 色 + 虚线底）。
2. **`.tbd-legend` 页级图例** —— 页脚上方一行："标色项为待核实/待补充数据，交付前请二次确认。"
3. **`.flagbar` 块级清单** —— 逐条列明待核实项（数据页/收尾页收口）；**一页内联标色 ≥3 处时优先用清单**。

### 硬纪律

- **标色项所在页必须有 `.tbd-legend` 或 `.flagbar`**（校验器检查）——只标色不解释，用户不知道为何标色。
- 单页 `.tbd` ≤ 12 处；过密说明这页数据整体不可信，应改为**待核实清单页**或先补数据。
- **不要把普通数字也标色**——标色贬值后用户会忽略真正的风险项。
- **不引入第二色相**：标色只用 `--accent` 系（`.tbd` / `.flagbar`），**不要**用红/橙等警示色（铁律 2）。
- PPTX 同源：模型 `section.flags: ["…"]` 导出为 accent 强调色清单条，并写入演讲者备注。

**✗ 只标色不解释（校验 FAIL）**：页内 3 处 `<span class="tbd">xx%</span>`，但全页无 `.tbd-legend` 也无 `.flagbar`——用户不知道哪些数字能信。
**✓ 收口**：≤2 处 → 页脚加 `.tbd-legend` 一行；≥3 处 → 改 `.flagbar` 逐条清单（哪项、等谁确认、何时替换）。

> 与 `.cite [n]` 的分工：`[n]` 是"有出处的外部数据"（可追溯）；`.tbd` 是"还没出处的待核实项"（待补）。**能查到出处的走 `[n]`，查不到才标 `.tbd`**。

## 六、章节骨架

每章固定四件套：

```
[eyebrow 小标] 0X · 关键词
[主标题]       一句主张/行动句（≤ 20 字；禁纯话题标签）
[导语]         ≤ 2 行，说明本章回答什么问题
[主体]         图 / 表 / 列表
```

结尾章：**下一步 3 条**（列表）（+ 参考资料——仅当存在真实来源）。


## 六-b、Mode A 主张 / 行动标题（action title）

> 仅 `data-mode="presentation"`。与 research「结论句 ≥12 字」同向，但演示可更短口语——**仍须是主张，不是话题**。

- ✗ 话题标签：「现状分析」「市场格局」「风险与挑战」「项目概述」「总结」
- ✓ 主张/行动句：「试点卡在治理——规模化分水岭已现」「Q3 增速转正，渠道贡献六成」「先守利润，再谈扩张」
- 一页标题 = 一页最重要的那个判断；写不出主张 → 先想清楚再排版。
- 校验：`validate_report` 对纯话题标题 **WARN**（硬 FAIL 过脆）；正式交付宜清零。

## 七、交付前自查（内容侧）

- [ ] 卡片里出现大段连续文字 → **转列表 / 拆卡**（勿删义凑疏朗）
- [ ] 一句话过长难念 → 断句或分条（勿截断加「…」）
- [ ] 外部数字没有 `[n]` → 补标记
- [ ] 占比数据只用文字 → 改环形图/条
- [ ] 同一屏 3 个以上主张 → 拆屏（证据可留作次要卡或跟进页）
- [ ] Mode A 标题是话题词（「现状分析」等）→ 改主张/行动句
- [ ] 出现"赋能/彰显/格局/不仅…而且/大幅提升" → 替换
- [ ] 结尾是"未来可期"式空话 → 换具体下一步
- [ ] 半空卡 **或** 塞爆一屏 → 调结构（两者都不合格）；禁止靠删证据「变空」
- [ ] 条目/结论被静默截断或 so-what 失踪 → 按 §四-c 重排/拆页，恢复实质
- [ ] 页高溢出却未拆页/未换形态 → FAIL 级缺陷，先结构后字号
- [ ] 图表小于尺寸下限（环形 <140px / 柱折线 <200px 高）→ 放大或减图
- [ ] 接近满屏的页（Hero/Agenda/收尾）没加 `band--fit` → 补上垂直居中
- [ ] 图表 svg 没有 `data-chart` 类型标记 → 补上（校验脚本要用）
- [ ] 图表颜色写死色值 → 改 `.f-acc`；多系列 → `.f-c1~c5`

## 八、research 模式内容规则（咨询论证 · 证据链）

> 以下规则仅 `data-mode="research"` 生效；与上文演讲规则冲突时，以本节为准。

### 8-1、论证结构（每页三段式）

1. **发现（Finding）**：直接陈述数据与事实，≤200 字/段；数字前置（"入湖表 68% 从未被查询"）。
2. **证据（Evidence）**：Exhibit 图表框 / 密表 / 指标带；外部数据必带 `[n]`；每个 Exhibit 必有来源行。
3. **结论条**：`.sowhat` 一行收口（≤60 字）——"这意味着…/因此建议…"；**不显示「So what」标签**；靠 MD3 tonal surface（`accent-soft` 满铺 + 细描边 + 舒适字阶/行高）强调——**禁止左侧 accent 装饰轨**（anti-AI-flavor）；写不出结论说明这页论证不完整。

### 8-2、行动标题写法

- ✗ 主题词式："现状分析" "市场格局" "风险与挑战"
- ✓ 结论式："入湖表 68% 从未被查询——资产沉睡是第一问题"（≥12 字，含具体数字或判断）
- 一页标题 = 一页最重要的那个结论；标题改好了，这页才算立住。

### 8-3、Exhibit 纪律

- 全篇连续编号（Exhibit 1..N），不跳号、不重复、不缺号（校验器检查）。
- 每页最多 1 个 Exhibit；`exhibit__t` 用结论式标题；`exhibit__src` 必写来源+时间+口径。
- 文内引用："如 Exhibit 3 所示"，不写"如下图"（翻页后"下图"指代失效）。

### 8-4、密度与版式

- 版式只从锁定版式 R1–R8 挑（见 `components.md` §36d–36f），不临场发明结构。
- 单页文字 ≤3200 字；卡片列表 ≤5 条；表格 ≤16 行（密表）；每 3–4 页一个 R4 指标带页做节奏休止。
- 双栏/三栏正文段落 ≤200 字/段；允许长论述（这是 research 的本职），但仍禁大段 AI 腔（第二节照常适用）。
- R6 三栏每栏 ≤150 字；R7 表图互证、表 ≤8 行小表；R8 矩阵 ≤3×3。

### 8-5、引用与来源行（克制条款）

- 页内关键数据 `[n]` 上标；**Exhibit 页来源行走组件自带 `.exhibit__src`**（不重复加）。
- 独立 `.footnote` 只在页内有关键外部数据且无 Exhibit 时才加——**不逐页加脚注**，不加多余页头角标/页脚信息行。
- 文末「参考资料」与 Exhibit 来源行、页内 `[n]` 三方对齐；同一来源多篇页可复用编号。

### 8-6、architecture 模式文字极简规则（模式 C）

- 每页文字只允许：eyebrow + 行动标题（≤20 字）+ 图注（1–2 行）+ 节点短标签（≤8 字）。
- 长说明全部转图注或拆到 research 模式报告；图为王，文字退到图注级。
- 内容页 ≤4 时**省略 Agenda**（封面后直接进图）；≥5 内容页建议补。
- 架构模式不要求图标（图标服务于叙述页，图为主角时不加噪音）。
